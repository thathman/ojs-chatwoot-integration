# v2 Licensing & Third-Party Boundary

## 1. Plugin licence decision

The OJS plugin must be released under an explicit GPL-compatible licence to qualify for the PKP Plugin Gallery.

Project licence decision for v2: **GNU General Public License version 3 (GPL-3.0)**, consistent with OJS/PKP licensing expectations and the PKP plugin template.

Before public release, the repository and packaged plugin must contain the full GNU GPL v3 text in a root `LICENSE` file.

Where source headers/SPDX identifiers are added, use a single consistent expression selected by maintainers (for example `GPL-3.0-only` if the project intends version 3 only). Do not silently switch to “or later” without an explicit licensing decision.

## 2. Copyright

Do not invent copyright holders, organizations or dates. Preserve existing notices where present and add project copyright notices only with accurate maintainer/owner information.

## 3. OJS/PKP relationship

OJS source is GPL v3. This plugin integrates with OJS plugin APIs, hooks, services and application classes. The plugin’s GPL-compatible licence is appropriate for distribution through the PKP ecosystem.

Do not copy OJS core files into the plugin except where a clearly permitted, necessary derived fragment is used with preserved notices. Prefer API/service integration.

## 4. Chatwoot licensing boundary

The current Chatwoot repository uses different licences by directory:

- content outside restricted directories is under the root MIT Expat terms;
- content under `enterprise/` is governed by `enterprise/LICENSE`;
- the Captain components inspected for v2 (assistants, documents, custom tools, scenarios, FAQ suggestions) are under `enterprise/`.

Chatwoot’s enterprise licence states that production use of that enterprise software requires the applicable Chatwoot Enterprise subscription/licence terms.

### Product implication

The OJS plugin does **not** vendor, redistribute or derive from Chatwoot enterprise implementation code. It integrates with a separately deployed Chatwoot instance through documented/observable network APIs and web-widget interfaces.

Therefore:

- the plugin can remain GPL-licensed independently;
- core Chatwoot widget/API bridge features should degrade gracefully when Captain is unavailable;
- Captain Intelligence is documented as an optional feature requiring a Chatwoot edition/plan where Captain Custom Tools/Documents/Scenarios APIs are available;
- administrators are responsible for complying with their Chatwoot licence/subscription terms;
- this project must not copy Chatwoot enterprise source into the plugin to bypass edition controls.

## 5. MCP licensing boundary

The plugin-owned MCP adapter is our code and is covered by the plugin/project licence. It does not depend on Chatwoot native MCP support and does not provide a mechanism to bypass Chatwoot licensing.

MCP clients such as OpenClaw are separate software; each retains its own licence. Document integrations without bundling incompatible dependencies.

## 6. Dependencies

Before stable release:

- inventory all bundled/runtime dependencies;
- prefer OJS/PKP-provided libraries where supported instead of vendoring duplicates;
- record dependency licences;
- ensure every bundled dependency is GPL-compatible for distribution in the plugin package;
- exclude development-only dependencies from the release archive when possible;
- keep third-party notices where required.

## 7. Remote services

Network integration with third-party services (Chatwoot, payment gateways, Crossref/DataCite, ORCID, etc.) does not automatically make those services or their data part of the plugin licence. Each integration must document:

- required account/plan/licence;
- API terms the deployer must satisfy;
- whether credentials/data leave OJS;
- whether the integration is optional;
- what happens if it is unavailable.

## 8. Data/content licensing

Journal content, manuscripts, reviews, user data and policies are not relicensed merely because the plugin processes them.

Generated support knowledge pages reproduce/transform journal-owned configuration/content for support purposes. Administrators remain responsible for the rights and policies governing their journal content.

Do not embed third-party copyrighted documentation wholesale into the plugin’s default knowledge base. Link to or extract administrator-owned/configured OJS content according to applicable rights.

## 9. AI output

Captain/MCP model responses are generated by the configured external AI/support system. The plugin’s GPL licence covers plugin source, not a blanket licence grant over generated support responses or underlying journal content.

## 10. Release checklist

Before Gallery submission:

- [ ] full GPL v3 text at repository root;
- [ ] full GPL v3 text included in packaged top-level `chatwootIntegration/` directory;
- [ ] README clearly states plugin licence;
- [ ] no incompatible bundled dependency;
- [ ] third-party notices included if required;
- [ ] Chatwoot Captain requirements described as optional/edition-dependent;
- [ ] no Chatwoot enterprise source vendored;
- [ ] no secret/API credential committed;
- [ ] maintainer/contact metadata is accurate and owner-approved.

## 11. Legal caution

This document is a product/release engineering policy, not individualized legal advice. If the distribution model changes materially (for example bundling proprietary SDKs, selling a modified Chatwoot enterprise distribution or embedding third-party content), re-review licensing before release.
