## MCP — MCP Adapter

- [x] **MCP-001** Select protocol/library implementation strategy. — decided and recorded in `docs/v2/ADRS.md` ADR-023: MCP revision `2026-07-28`, stateless Streamable HTTP transport (no deprecated HTTP+SSE, no STDIO), custom protocol layer isolated under `classes/v2/Mcp/` rather than a required `mcp/sdk` runtime dependency (pre-1.0/experimental; this plugin ships no runtime Composer tree today). - [x] **MCP-002** Define MCP authentication/client model. — `McpAuthenticator` (own distinct entry point, deliberately not just a Support API call site reused, even though it shares `ServiceTokenAuthenticator`'s generic Bearer-match algorithm — the credential *namespace* it must never share is the configured secret value, per ADR-023). `McpPublicConsumer::baseCapabilityRequest()` defines the public MCP consumer model: always `CONSUMER_MCP_PUBLIC_SUPPORT` at `v0` (unverified) — proven to unlock exactly the same baseline capability set an unverified Chatwoot Captain caller gets, never more, and proven that an authenticated-but-unrelated MCP context still cannot reach a resource-scoped capability without an actually-proven relationship. No new session model is needed. - [x] **SEC-004** Cross-conversation session replay test. — `tests/v2/support-session.php`: a session bound to one exact (context, account, contact, conversation) tuple is proven to reject resolution against a different conversation id, a different contact id, and a different journal — each independently, using the same bound session. Also covers the adjacent one-time binding-token replay (a consumed binding token must reject a second bind attempt) and cross-context/cross-user binding rejection.
- [x] **SEC-005** OTP brute-force/rate-limit test. — `tests/v2/external-verification.php`: brute-force lockout after `maxAttempts` (4) wrong PINs, with the genuinely correct PIN still rejected once locked (not a soft warning); per-conversation and per-identity rate limits independently exercised until each threshold is hit and `requestChallenge()` returns null.
- [x] **SEC-006** Prompt-injection/tool-abuse test. — `tests/v2/prompt-injection-tool-abuse.php`. Found and fixed a real gap: `HandoffSummaryFormatter::sanitizeReason()` stripped control characters but never newlines, so a crafted `reason` (the one field an attacker or a prompt-injected Captain relaying one can influence) could inject a fake `- Field: value` line or even a fake second `**Support Gateway Handoff**` header into the rendered private note, forging structured facts a human agent or a later-summarizing LLM might mistake for real. Fixed by collapsing newlines/tabs to spaces before capping — the reason's actual content is fully preserved, only its ability to spoof a new structural line is removed. Also asserts, source-wide, that every real `->allows(...)` authorization call site is always a fixed string capability name, never a variable derived from free text, and that the one endpoint carrying an attacker-influenceable field (submission title) evaluates its capability check before ever reading that field.
- [x] **SEC-007** Secrets absent from browser/logs/export. — covered across per-surface tests rather than one consolidated check: `tests/v2/live-plugin.php` (settings export redacts `chatwootApiAccessToken`/`chatwootIdentityValidationSecret`/`chatwootSupportApiToken`), `tests/v2/audit-logger.php` (the persisted audit sink allowlists exactly six safe fields, dropping anything else even on its DB-failure fallback path), and multiple serializer tests (`submission-support.php`/`publication-status.php`/`required-actions.php`/`blind-review-anonymity.php`) forbidding `email`/`reviewer_id`/`token`/etc. in their output.
- [x] **SEC-008** Public knowledge contains no protected data. — `tests/v2/knowledge-compiler.php`: a provider emitting a `KnowledgeClassification::PRIVATE` fact and an `UNSUPPORTED` fact are both proven to never survive into the compiled/rendered output — `KnowledgeCompiler` keeps only facts classified exactly `PUBLIC`.
